# ADR-001：MVP 范围与架构决策

- 状态：Accepted（2026-08-03，待产品/研发/安全负责人最终评审确认）
- 日期：2026-08-03
- 决策人：项目技术负责人

## 背景

闲鱼低价商品监控系统需要明确 MVP 边界与关键技术决策，避免范围蔓延与方向漂移。

## 决策

### MVP 范围

1. **只做"发现并通知"**：用户创建关键词监控任务 → 定时采集 → 清洗去重 → 记录价格历史 → 计算市场价基线 → 识别低价 → 发送通知。
2. **明确不在 MVP 范围**：自动下单、代购、竞价、账号批量操作、批量强聊、收藏夹/卖家行为分析。
3. 数据采集仅接入**官方 API、书面授权的合作数据源或用户明确授权的公开数据**；不设计验证码绕过、风控绕过、账号池、代理轮换、签名逆向。

### 架构决策

1. **规则引擎优先于模型估价**：MVP 用"用户价格阈值 + 简单市场基线（中位数 + IQR 剔除）"判定低价；后续（Phase 2+）再引入估价模型。
2. **异步事件链路**：采集/清洗/分析/通知通过消息队列解耦（拓扑见 `packages/queue/src/topology.ts`），API 不直接执行耗时采集。
3. **浏览器采集封装**：Playwright 仅作为数据源适配器的执行层（ADR-005），业务层不感知页面结构。
4. **金额整数分、时间带时区**：全链路金额使用整数分（BIGINT/number），时间使用 ISO 8601 带时区。
5. **事件契约先行**：`RawProductEvent` → `ProductObservedEvent` → `LowPriceMatchEvent` → `NotificationCommand` 四级事件均带 `event_id`/`occurred_at`/`schema_version`，消费幂等。
6. **多租户隔离**：监控任务、通知记录按 userId 归属；API 层所有权校验（他人资源 404）。

### MVP 退出条件

- 用户可完成：注册登录 → 创建关键词监控 → 系统按频率采集 → 命中低价（含可解释原因）→ 站内信/邮件/企业微信通知 → 查看商品与价格历史。
- 低价命中保留规则版本、市场基线、阈值与原因（可追溯）。

## 风险清单

- 数据源授权（EXT-001）未到位前，真实采集链路（COL-002）无法验收。
- 通知渠道凭据（EXT-002）未到位前，邮件/企微真实投递无法验收。
- 误报/漏报评价样本集尚未建立（PRI 验收依赖）。
